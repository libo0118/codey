# Agent Note: Windows Rust 测试进程的并行预算

Status: implemented

## Problem

发布 CI `41581957115` 的两次 Windows 执行分别有一项、五项 Webhook 异步测试超时，失败涉及发现、入队、HTTP 进度和持久化确认；同一业务源码此前在 Windows 完整通过，Linux 也通过。现有日志不足以区分测试间资源争用与实际投递阻塞，不能宣称已定位产品缺陷。

## Decision

Windows 质量检查和打包流程只在 Rust tests 步骤设置 `RUST_TEST_THREADS=2`，以有界测试间并行度运行完整测试集；Linux 不变。测试内部 Tokio 任务、四路 HTTP 并发、渠道串行、持久化配置和所有时限保持原样。

此设置约束 CI 测试进程的资源预算，不调整生产通知行为，也不替代并发压力测试。限制并行度是否消除这些超时由新 CI 验证；单次通过不能证明原始故障根因。

## Alternatives considered

- 原配置重跑：不改代码，但第二次重跑已有更多测试超时，不能继续靠重复尝试获得绿色结果。
- 放宽测试时限：可以容忍慢机器，但会削弱原有入队和投递进度约束，当前没有证据支持改变这些契约。
- 修改 SQLite 持久化或投递实现：可能影响实际阻塞，却缺少阶段证据，不能为了发布改变用户数据可靠性。

## Consequences

- 全量测试仍执行，内部并发断言仍有效；测试耗时可能增加，对更高测试间并行度的覆盖减少。
- `tests/release-quality-gates.test.mjs` 先验证旧配置失败，再验证两处 Windows 步骤一致且 Linux 不受影响；该静态检查不代替 Rust CI。
- 若限制后仍超时，停止调整并行度或时限，采集 HTTP、队列和存储边界证据。恢复更高并行度需有可重复的压力验证，不以本设置证明产品高负载正确性。
