# Agent Note: Owl 桌面的渲染启动兼容

Status: implemented

## Problem

Linux Owl 包在启用 CDP Fetch 拦截后停在启动页，且不产生 `Fetch.requestPaused`，因此错误放行、缓存重建或延长等待都不能修复它。同一安装、同一份桌面资料副本、隔离的空 `CODEX_HOME` 中，暂停目标再恢复可正常完成前端初始化；加入 Request 或 Response 阶段的 Fetch 后，均停在 `interactive` 且没有 React root。该对照不发送模型任务，不修改生产会话。

## Decision

- Linux 安装同时具有 `owl-shell-runtime.json` 和 `resources/owl-electron-app.json` 标记时，只保留运行时桥接，不启用不兼容的 Fetch 资产改写，也不扫描其改写缓存；其他安装保持原行为。
- 浏览器级挂载仍恢复新页面，CLI 包装器、Hook、认证、审批和既有模型请求门禁不变。不强制设置 ready，不修改代理、密码或沙箱参数；依赖静态改写而运行时又未取得的能力保持不可用。
- 通过兼容诊断事件明确记录未启用静态资产改写。这是已确认安装包的兼容边界，不新增用户开关或对所有 Linux 客户端停用增强。
- 新建适配器复用会话读取已有的源码注册表解析器：未经过静态改写的原生包不导出管理器查找类，不能只查模块导出。读取创建输入仍使用同一 scope 的原生工厂，保留工具、项目指令及权限默认值；新适配器版本与源码查找能力一起校验，旧安装要求正常重启，不重装或销毁进行中的桌面会话工具。

## Alternatives considered

- 清理缓存或禁用 GPU：容易回滚，但没有改善现场初始化结果，恢复原设置。
- 改为 Response 阶段拦截：保留原资产改写流程，但隔离对照同样停滞，没有请求事件。
- 强行放行远程写操作或启用只读预览：前者绕过校验，后者不符合用户保留实时操作的决定，均不采用。
- 全部客户端禁用资产改写：范围过大；仅识别实际 Owl 安装标记，不影响普通 Electron 客户端。

## Verification

回归验证 Owl 标记选择仅作用于 Linux，运行时模式在新页面创建时直接恢复而不发送 Fetch 命令；普通客户端仍先完成拦截再恢复页面。真实远程读写、模型门禁与完整 Rust CI 必须另行验证，不能把隔离启动或测试代码存在当成完成。

## Consequences

Owl 的启动不再依赖不支持的拦截域；部分静态源码增强暂不可用，运行时无法恢复的功能不得假装成功。此修复不实现超过 64 MiB 的原生实时历史分页。

与[上游适配](2026-11-04-upstream-151-compatibility.md)部分重叠：保留其普通客户端 Fetch 流程，只增加已验证 Owl 运行时的例外；其他活动笔记没有对应旧提案需要归档。
