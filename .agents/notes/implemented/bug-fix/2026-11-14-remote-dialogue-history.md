# Agent Note: 更早历史按对话记录分页

Status: implemented

## Problem

首屏按非空对话计数，但 `MessageWindow` 扩展阶段把每条过程活动都算进历史配额和字节预算，工具密集时用户点击后主要看到过程。用户要求更早内容改为对话记录，而非过程历史。

## Decision

- 首屏及后续分页共用对话判定：用户／助手公开正文、纯附件和公开错误属于记录，过程和空消息不占对话配额。
- 追加的更早历史只展示对话记录；保留进入时的近期活动与之后的实时过程，维持原始顺序、展开状态和阅读锚点，不删改 Native 历史。
- 本地窗口没有更早对话且 Native 历史未加载完整时，同一次显式读取等待 Native 补读后追加记录；读取失败结束加载态并允许手动重试，不自动重试或影响写入防重。
- v2 增加每连接 `historyRevision` 读取完成计数，不再把过程变化、首条消息删除或实时回复当成历史回执；它不参与文件权限判断。已发布旧流没有此字段时仍沿用对话边界确认。
- 旧完整快照协议不变；公开投影裁剪不改变文件绑定、权限或当前执行状态。

## Existing-note audit

[有界公开流](../../implemented/architecture/2026-11-04-bounded-remote-stream.md)的首屏、增量和权限边界保留，历史扩展计数及过程混入由本篇细化；[移动层级](../../implemented/feature/2026-11-12-remote-mobile-layout.md)的过程按需展开与阅读暂停规则保留，仅更早追加记录不呈现过程。

## Alternatives considered

- 只改按钮文字最省代码，但不修复活动吞掉分页配额的问题。
- 只在浏览器隐藏过程保留服务器按条目计数，会出现点击后没有新增对话，仍传输大量工具数据；在共享分页层选择记录。
- 移除所有过程可以简化列表，但会丢失当前任务的公开执行信息；只过滤追加历史中的过程。

## Testing

- Node 先跑出 Native 历史补读／加载态与过程先行反例，修复后覆盖单次显式补读、RPC ACK 不当成记录送达、失败手动重试、旧登录／会话、401、读取回执字段及滚动锚点。
- Rust 回归覆盖密集过程中的 50 条对话配额、纯附件、纯过程无入口、近期活动保留、Native 延迟补读及首条实时消息不能伪装历史完成；本机缺少 Rust 标准库／链接环境，原生执行由 CI 核验。

## Consequences

较早过程不再由此入口呈现，仍可在原桌面端查看；单条大正文或预算可能使一页少于固定配额。当前任务正在工作时，不未经新授权部署重启。
