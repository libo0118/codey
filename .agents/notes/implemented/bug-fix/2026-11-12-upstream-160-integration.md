# Agent Note: 同步正式版 1.6.0 并保留移动端与子代理边界

Status: implemented

## Problem

集成分支需要同步正式版 1.6.0 的设置页、模型目录、扩展管理与运行时改进。重叠文件还承担 Linux 支持、自定义角色、严格子代理门禁和原生直连计时，不能直接用上游整份文件覆盖。

## Decision

- 合并正式标签 `v1.6.0` 指向的 `629ec69206e81f8ec526fb9f2a3c053f9d213577`，源码候选版本为 `1.6.0-libo.1-preview.1`。移动端改动独立提交；本次不创建发布标签、不发布、不安装。
- 采用上游模型缓存、扩展管理、设置页预计算与开关优先布局；保留本分支运行管理分组、独立网络代理页、自定义角色注册／编辑／显式删除、可配并发和失败派发恢复。每个角色只保留一个启用开关。
- 保留 Explorer 当前轮原生只读证明、未知工具与包装器限制、Reviewer 源码写入限制；并发配置只发出规范键，不恢复重复别名。新缓存入口与同步类型保留 Linux 条件编译。
- 统计保留上游展示改进与本分支原生／路由来源隔离。注入版本采用 19，确保已发布的本分支 17 与上游 18 都能释放旧监听器并被新实例替换。

## Existing-note audit

[1.5.6 集成](2026-11-11-upstream-156-integration.md)保留既有权限、数据来源和公开构建边界，本记录承接新正式版；[自定义角色](../feature/2026-11-04-custom-subagents.md)、[并发配置](../feature/2026-11-04-subagent-concurrency.md)与[失败派发恢复](2026-11-06-failed-spawn-recovery.md)继续约束运行时，不被界面合并替代。

## Alternatives considered

- 完全采用上游文件可以减少合并差异，但会丢失 fork 的 Linux、角色管理与权限边界；只合入对应改进。
- 保持旧设置页可以减少测试调整，但会漏掉上游交互优化；沿用新布局并覆盖本分支新增菜单之间的键盘切换。
- 等待 GitHub Actions 转运源码可以复用 CI 环境，但正常 Git 拉取已恢复；直接拉取正式标签，删除临时转运分支，不扩大仓库设置变更。

## Verification

TypeScript 检查、前端生产构建与统计／设置页 84 项回归通过。全量 JavaScript 回归共 1626 项，1622 通过、3 跳过，唯一失败为 Python scaffold 测试因本机缺少 `cargo` 无法执行。首次识别出的两个集成断言已随保留的菜单和注入版本补测。Rust 编译、测试和 lint 尚未获得本轮通过证据，不把源码合并等同于原生验收。

## Consequences

正式版功能与 fork 边界同时保留，后续合并仍需维护少量冲突。候选源码版本不代表已有 Release 或安装包；已运行的桌面程序、远程服务与 HAP 不会被本地合并替换。
