# Agent Note: 上游合并中的会话选择边界

Status: implemented

## Problem

合并上游 `5364c29f` 时，fork 的整轮 mutation drain 与上游有界分帧队列重叠。仅把选择入口改成邻近轮刷新，会漏掉复用 DOM 中远处的旧会话选择锚点：切换会话后 Shift 点击可能把未选择的轮次加入删除请求，删除前再全量刷新也无法撤销这些选择。

## Decision

后台 DOM mutation 采用上游单一有界队列、分帧和邻近轮扫描；用户选择和删除入口都先整会话刷新。性能预算只约束可选控件发现，不替代用户操作所需的会话身份与选择状态校验。

合并保留 fork 的会话复用隔离、幂等 DOM 写入、原生 Fast/Ultrafast 资格、原生遥测和思考档位同步。模型同步复用上游动态系统代理客户端，Linux 启动同时保留 fork 支持和上游标题任务 relay。模型与统计注入版本分别更新为 `84`、`9`，使旧安装执行热替换，而不是复用版本号相同但行为不同的旧实现。

## Alternatives considered

- 保留 fork 的整轮 drain：能完整发现轮次，但会失去上游新增的有界调度；同时保留两套队列又会产生冲突的刷新与清理语义。
- 所有入口都只扫描邻近轮：用户操作成本较低，但已通过跨会话远距离 Shift 复现证明存在错误删除范围，不能用于选择入口。
- 直接采用上游文件：冲突最少，但会丢失 fork 的原生资格、会话隔离及遥测等定制。

## Consequences

- 用户选择时允许整会话扫描，后台 mutation 仍受预算限制；超量时可以跳过早期可选按钮发现，显式全量刷新仍能恢复全部轮次。
- `tests/completion-tracking.test.mjs` 的远距离跨会话 Shift 回归先证实会错误请求删除三轮，再验证修复后仅请求目标轮次；相关四组测试共 146 项通过。
- Rust 工具链缺失，后端合并经过调用链和静态契约复核，但尚未完成 Rust 编译或实机启动验收。
