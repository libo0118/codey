# Agent Note: 自定义子代理的配置、删除与运行时边界

Status: implemented

## Problem

固定角色白名单使自定义子代理即使出现在页面也会在保存、备份或运行时被丢弃。仅移植 CodeyX 页面不足以形成可用功能；按完整矩阵缺席推断删除，又会让旧客户端或部分更新误删角色。

## Decision

- 选择性适配 CodeyX `30e1daa4861762626628e6c2805366cd6519e6f2` 的角色矩阵、编辑界面与运行时注册，保留本仓默认及五个内置角色、固定并发和模型能力策略。复用 `load_codey_config` / `save_codey_config`、revision 与备份格式，不新增 CRUD 服务或全局原生代理安装器。
- 自定义角色保存显示名称、用途、指令、模型、思考强度与读写能力；标识符限制为安全名称，数量和 UTF-8 字节数在配置、命令与备份边界共用校验，非法提交在写入前拒绝。默认只读，旧内置角色保持既有权限。
- 普通提交中缺席的角色保持不变，只有 `config.deletedSubagentRoles` 明确指定的自定义角色删除；删除意图不持久化、不返回，内置角色不得删除。备份恢复仍以完整备份矩阵为准，避免把普通部分更新规则套到恢复操作。
- 页面使用现有草稿与显式保存，删除先确认，验证或后端失败保留草稿。通知渠道即时保存遇到未保存设置时拒绝，避免顺带提交角色更改；重启确认明确提示会保存全部未保存设置。网络代理从基础功能迁至唯一独立入口，不另建配置或改变代理语义。
- 角色仅供 Codey 启动的 Codex 运行时加载，不修改用户原生代理文件。检查已知全局 `[agents]` 与 `agents/*.toml` 声明的名称冲突，原生文件读取有界且链接、损坏时拒绝；不扫描用户全部项目，不接管项目原生角色。自定义运行时文件带角色绑定的受管标记，已有同名未知普通文件拒绝覆盖，符号链接及重解析点拒绝；不枚举清理目录中的其它文件。
- 已注册角色与派发策略通过现有文件、lease、policy 事务更新并回滚；新角色待重启。角色启停、权限及模型变化只影响后续派生，已活动 attempt 沿用派生时配置，停用或删除不等于中止旧任务；身份和终态结算沿用上游，不增设 custom 的额外终态身份屏障。
- 新派生只读角色同时收窄工具能力并使用原生只读配置；可读写不主动覆盖父任务沙箱。Hook 不构成独立系统沙箱，也不能替代用户在降权前结束已有任务。

## Alternatives considered

- 直接复制参考版完整矩阵保存及目录清理：适配成本最低，但旧客户端遗漏字段会被解释成删除，仅凭合法文件名清理会误碰未知文件；采用显式删除和角色绑定的受管标记。
- 直接写入用户原生 `agents/`：符合当前[官方子代理文档](https://developers.openai.com/codex/subagents/)的独立文件机制，但会扩大到全局安装、覆盖与项目优先级管理，并绕开既有生命周期；本次只提供 Codey 受管运行时。
- 保存时中断或追溯降权活动子代理：撤权更直接，但改变现有任务配置快照语义，原生已启动沙箱也不能安全热切换；保留下一次派生生效，并明确提示旧任务边界。

## Consequences

- 备份与运行时现在识别同一自定义角色矩阵，旧配置和部分客户端更新不会默默删除角色；代价是新角色要重启，原生代理冲突或未知同名运行时文件需要用户先处理，不能保证所有项目原生角色名称都已检查。
- 行为测试覆盖草稿、删除、保存失败、旧客户端、配置保留、原生冲突、同名文件拒绝覆盖、热更新回滚、只读工具门禁及备份往返；测试存在不等于真实 Codex 派生通过。本机原生 CLI 仅确认顶层 `agents` 配置能解析，损坏或缺失的角色文件在该命令中也未触发读取，不能将其当作角色加载证明。
- 按子代理、角色、代理优化关键词检索活动笔记，与[远程及数据边界](../architecture/2026-11-03-codeyx-remote-and-data.md)和[内置工具管理](2026-11-03-codeyx-managed-tools.md)互补；预览分支的保留范围与生命周期回退见[选定能力方案](../simplification/2026-11-04-selected-custom-preview.md)，不覆盖自定义角色及工具安装边界。
