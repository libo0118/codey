# Agent Note: 子代理并发数量与运行时策略保持一致

Status: implemented

## Problem

固定两个子代理不适合不同机器的资源预算。只增加页面数字会让配置、Codex 原生限制、派发提示与工具门禁互相矛盾；热改上限又可能使已有任务突然被中断。

## Decision

- `subagentMaxThreads` 保存和备份同用现有配置流程，只接受 1..64 的整数，默认 2，不含根代理；缺席字段的部分提交保留原值，非法输入在配置、备份和运行时边界拒绝。
- 启动时把同一值写入原生 `agents.max_concurrent_threads_per_session`、运行时 lease、门禁策略及派发提示。有效配置和启动参数只保留这一键，不同时输出其别名 `agents.max_threads`；Codex 的角色加载器会因重复字段丢弃该配置层的全部角色。用户原始配置文件不改写。角色热更新继续使用启动时的 limit，不拿待重启的草稿替换运行中策略。
- 改数量保存后要求重启，不杀旧任务、不追溯改变已派生角色或权限；最多 32 个自定义角色的规则保留，原五个内置角色按[上游 v1.5.2 整合](../bug-fix/2026-11-06-upstream-152-integration.md)迁移，内部 `default` 沿用。

## 活动笔记审计

本篇部分取代[自定义角色](2026-11-04-custom-subagents.md)的固定并发决定，保留旧理由并互链；[选定 custom 范围](../simplification/2026-11-04-selected-custom-preview.md)继续约束不恢复额外生命周期补丁。远程文件和消息投影不涉及本决定，无过时提案需要删除或归档。

## Alternatives considered

- 保持固定两个：实现简单且资源可预测，但不能满足用户明确要求的配置能力。
- 保存即热改或中止超额任务：生效更快，但会改变活动任务的配置快照语义；选择重启生效。
- 同时输出新旧并发键看似能兼容不同运行时，但当前 Codex 将它们视为同一字段，导致 `unknown agent_type`；只输出公开规范键，不新增角色全局安装或修改门禁。

## Consequences

配置、备份、原生参数与门禁使用同一来源，代价是生效要重启，较高上限的资源消耗由用户承担。合成回归覆盖保存缺席、边界值、备份、两个启动路径与策略一致性，并禁止输出重复并发别名。Codex `0.167.0-alpha.3.2` 的隔离 app-server 使用回环模拟模型已验证双键重现 `unknown agent_type`，单键恢复角色注册、创建、回传及完成；这不替代 Codey 新二进制的编译验证或真实模型的桌面验收。
