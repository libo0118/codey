# Agent Note: 子代理并发数量与运行时策略保持一致

Status: implemented

## Problem

固定两个子代理不适合不同机器的资源预算。只增加页面数字会让配置、Codex 原生限制、派发提示与工具门禁互相矛盾；热改上限又可能使已有任务突然被中断。

## Decision

- `subagentMaxThreads` 保存和备份同用现有配置流程，只接受 1..64 的整数，默认 2，不含根代理；缺席字段的部分提交保留原值，非法输入在配置、备份和运行时边界拒绝。
- 启动时把同一值写入原生 `agents.max_threads`、既有会话并发项、运行时 lease、门禁策略及派发提示。角色热更新继续使用启动时的 limit，不拿待重启的草稿替换运行中策略。
- 改数量保存后要求重启，不杀旧任务、不追溯改变已派生角色或权限；默认、五个内置角色与最多 32 个自定义角色的规则不变。

## Alternatives considered

- 保持固定两个：实现简单且资源可预测，但不能满足用户明确要求的配置能力。
- 保存即热改或中止超额任务：生效更快，但会改变活动任务的配置快照语义；选择重启生效。

## Consequences

配置、备份、原生参数与门禁使用同一来源，代价是生效要重启，较高上限的资源消耗由用户承担。合成回归覆盖保存缺席、边界值、备份、两个启动路径与策略一致性；Rust 原生运行和真实 Codex 派发仍需 CI 及主代理验证。
