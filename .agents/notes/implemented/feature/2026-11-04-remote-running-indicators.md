# Agent Note: 远程会话列表的可信运行运行标记

Status: implemented

## Problem

库存只有标题和更新时间，不能说明任务是否仍在执行；电脑在线、历史 inProgress 或旧运行标记缓存也不能充当当前运行状态。查询装饰性状态不能启动、恢复或切换会话。

## Decision

- 保留库存、正式标题和子代理过滤，在已有列表结果上附加 `running`：真实 active 为 true，明确 idle/systemError 为 false，其余为 null。状态结果不增加列表项，不进入数据库或 localStorage。
- 只通过已经连接的 hosted 原生接口执行 metadata-only `thread/read`，不信任可能卡住的执行缓存。查询有界并释放 pending，连接替换后整批失效；legacy、旧注入、未加载或无法确认的状态保持未知，不为覆盖这些情况启动 native 连接。旧主注入不整段热替换，独立远程适配器沿现有版本机制更新。
- 可见且联网时约五秒单 flight 刷新，恢复焦点、可见或联网即重新查询；首次和手动读取由实际网络请求决定成功或失败，不让 WebView 的网络提示阻止读取并伪装成空目录。列表读取独立限时，不改变写操作时限。失败、过期、隐藏或退出清除旧运行标记，迟到结果不能点亮新会话或新登录。已选会话的有效流更新可即时覆盖旧查询，终态、断线和无效帧清点；状态未变不重建目录数组。运行标记只做展示，不参与发送、停止或审批权限判断。
- 复用项目及最近列表的同一个行组件，只在严格 true 时显示可访问橙色运行图标与右侧中性 spinner，否则显示已有时间；保留标题、菜单及单行布局。呈现采用 [Cindy 页面切片](../architecture/2026-11-13-cindy-page-slices-and-dom-v2.md)，状态来源不变。

## Alternatives considered

- 直接使用缓存的 inProgress：读取便宜，但现有完成态校准已经证明缓存可能卡住，因此只采用新鲜原生状态或未知。
- 像参考项目一样为每行 attach/follow：覆盖面更广，但 Codey 现有 follow 路径可能打开会话且会增加连接；选择复用既有连接，并接受旧接口未知。
- 持久化运行标记或保留失败前状态：重载时展示稳定，但离线后会继续暗示任务在执行，因此不存储展示状态。

## Verification

定向回归覆盖真实活动、终态、未知、查询超时、连接替换、pending 释放和首次读取已有连接；前端覆盖定时刷新、旧响应、搜索、归档、登录切换、断线和流更新优先级。隔离 Mock 使用生产组件检查 320/390px 布局，不作为真实 Codex 或手机联动证明；Rust 可执行验证交由 CI，本机只有格式及 metadata 证据。

## Consequences

运行状态与库存身份来源分开，未增加远程权限或模型调用；代价是非选中会话有轮询延迟，慢请求及不支持的原生接口不亮点。字段缺失同样不点亮，兼容已发布预览的旧列表响应；网络或原生状态未知不代表任务已结束。

按运行标记、运行状态、会话库存及 thread/read 检索活动笔记：[库存身份与标题](../bug-fix/2026-11-04-remote-thread-inventory.md)和[远程及数据边界](../architecture/2026-11-03-codeyx-remote-and-data.md)互补，不改变其决定，无过时提案需归档。参考为 `codex-mobile-bridge@3a54f373` 的 `web/features/chat/activity.js`、`web/shell/app.js` 和 `bridge/app/service.py`，不复制其旧状态持久化或忽略刷新失败的行为。
